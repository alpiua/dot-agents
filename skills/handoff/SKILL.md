# Handoff

Use at the end of every significant delivery or session before concluding.

## Reconcile closure

1. Read the task, plan, Contract, and repository `AGENTS.md`, then load this
   skill's `ADDON.md` when the repository supplies one.
2. Confirm final review, required checks, accepted claims, required seams, and
   repair evidence apply to the current settled inputs.
3. Update the owning task or plan with completed scope, deferred work, evidence
   references, and known operational follow-up. Keep the task open when an
   accepted claim lacks current evidence or a material blocker remains.
4. Run repository-specific closure and derived-artifact procedures. Report an
   unavailable optional freshness mechanism as a handoff warning, never as
   fabricated success.

## Learn from delivery

When the delivery had a task Contract, load `contract-planning` and its
repository add-on. Apply its Handoff learning procedure to the session's
Contract changes, review findings, and failed or misleading checks. It may
admit zero or more independent verified local rules; it never records a session
transcript or creates new Contract authority.

## Report

State the outcome, verification performed, remaining blockers, deferred work,
and next action. Do not create a separate session-state file unless the
repository procedure explicitly requires it.
